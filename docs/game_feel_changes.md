# 조작 반응 변경

## 구현

`app.js`, `style.css`, `index.html`, `MainActivity.java`에 적용했다.

| 행동      | 시작·진행                                     | 확정·회복                                                 | 공간·다음 행동                          | 반복·실패                                     |
| --------- | --------------------------------------------- | --------------------------------------------------------- | --------------------------------------- | --------------------------------------------- |
| 필터·탭   | 눌림 즉시 명암과 깊이 변경                    | 선택 상태 즉시 유지, 내용 8px 진입·180ms 복귀             | 입력을 애니메이션으로 막지 않음         | 같은 노드 애니메이션 취소 후 새 반응          |
| 카드·상세 | 클릭 즉시 선택, 상세 32px 우측에서 220ms 진입 | 현재 프로젝트·대화 표시                                   | 배경 hidden, 뒤로 시 스크롤·포커스 복원 | 요청 중 다른 카드로 바꾸면 마지막 대상 재조회 |
| 대화 갱신 | 실제 요청 중 회전 표시                        | 메시지 ID·텍스트가 같으면 노드 유지                       | 바닥에서 읽던 경우에만 새 메시지로 이동 | 이전 대화는 기존 위치 유지                    |
| 입력·전송 | 입력란 48~144px, 3500자 초과 때만 카운터      | 전송 잠금·화살표 이동, 서버 sent에서 260ms 복귀·확인 햅틱 | 완료 문구가 폴링으로 지워지지 않음      | 연타 차단, 거부 시 초안·실패 표시 유지        |

공통 눌림은 80~90ms 명암·내부 그림자와 자식 요소 2px 이동이다. 클릭 영역과 실제 레이아웃은 유지한다. 화면 전환은 `cubic-bezier(.2,.8,.2,1)`을 사용한다. 상태 변경 테두리 강조는 500ms다.

목록의 경로·중복 제목, 상세의 터미널 주소·턴 수·대화 제목 라벨·추가 지시 라벨을 제거했다. 상태·기기·프로젝트·실제 대화와 실패 이유는 남겼다. 넓은 화면은 두 열, 좁은 화면은 한 열이며 조작 버튼은 최소 44px이다.

## 오디오·햅틱

소리는 추가하지 않았다. 에이전트 모니터에서 반복 클릭·폴링 소리는 정보량보다 방해가 크다. 직접 누른 조작에는 Android `VIRTUAL_KEY`, 서버 전송 확인에는 `CONFIRM`, 거부에는 `REJECT`를 연결했다. 시스템 햅틱 설정을 존중하고 모션 감소에서는 앱 햅틱도 생략한다. 강도의 적절함은 사람의 확인이 필요하다.

## 보존한 규칙

Tailscale·인증·서버 라우트·메시지 ID·승인 대기 차단을 유지한다. 애니메이션 완료에 요청이나 성공 판정을 연결하지 않는다. 실제 작업 에이전트에 시험 지시를 보내지 않는다.

`prefers-reduced-motion`에서 전환·반복 애니메이션을 끄며, 실행 중 설정 변경 시 이미 돌던 Web Animation도 취소한다. 정적 선택·상태·진행 문구는 남는다. 페이지가 숨겨지면 기존 폴링 중단 규칙을 유지한다.

- Chrome 경로는 `CHROME_BIN`으로 지정할 수 있다. 가상 테스트는 실제 브리지에 접속하지 않는다.
- 산출물: `artifacts/design-demo-list.png`, `design-demo-chat.png`, `design-checks.json`. 가상 대화로 생성한다.

## 남은 확인·롤백

햅틱의 손맛과 장시간 사용 피로는 사람의 확인이 필요하다. rAF 간격은 장치 입력부터 화면까지의 지연이나 체감 점수가 아니다. 브리지·세션 파서 변경은 이번 범위에 없다. 롤백은 이번 UI 변경 파일을 기준 커밋과 대조해 되돌린 뒤 APK를 다시 만든다.

## 0.3.1 입력·진행 표시 수정

0.3.0 실기기에서 카드의 표시 영역과 터치 판정이 어긋났다. `elementFromPoint`가 카드 대신 `#app`을 반환했으며, 목록을 다시 배치하면 복구됐다. 단순 `.click()` 검증은 이 문제를 찾지 못했다. 정확한 WebView 내부 원인은 확정하지 않았다.

긴 목록 전체의 진입 애니메이션과 inert 전환을 없앴다. 상세를 열면 배경을 hidden으로 숨기고, 닫으면 복원한다. 끝난 Web Animation은 명시적으로 취소해 표현 레이어를 정리한다. 상세 진입과 버튼의 국소 반응은 유지한다.

진행 메시지 외에도 대화 아래에 도구 실행·완료 상태를 표시한다. Codex의 `AgentMessage` 이벤트도 읽고 response_item과 중복 제거한다. Codex·Claude 도구 호출에서는 종류·진행 상태·시각만 반환하며 명령 원문·출력·추론은 반환하지 않는다. 작업 완료 상태에서는 진행 표시를 숨긴다.

검증: Python 9개, Node 8개, UI 44개 통과. UI 검사에 좌표 터치 12회 왕복을 추가했다. 폰에서는 필터 변경을 포함한 8회 왕복과 세 기기의 카드 진입을 실제 터치 이벤트로 확인했다. 진행 메시지와 도구 실행→완료 갱신을 확인했으며 실제 에이전트에는 시험 메시지를 보내지 않았다. APK 0.3.1 설치와 브리지 재시작 완료. 실기기 검사는 `node scripts/phone-navigation-check.mjs`로 실행한다.

## 0.4.0 전송·정렬

전송 버튼을 누르면 원문과 전송 ID를 로컬에 보존한 다음 입력창을 즉시 비우고 채팅에 `보내는 중…`으로 표시한다. 확인 전 새로 입력한 초안은 전달 완료 응답이 와도 지우지 않는다. 서버 대화에 같은 사용자 메시지가 들어오면 임시 메시지와 합친다. 전송 거부는 원문을 복원하되 새 초안을 덮어쓰지 않는다. 전달 여부가 불명확하면 경고 상태로 남기며 자동 재전송하지 않는다.

작업 중인 세션을 먼저 배치하고, 각 그룹은 실제 에이전트 응답 시각의 내림차순으로 정렬한다. 사용자 메시지·도구 출력·추론은 응답 시각에 포함하지 않는다. 작업 시간은 Codex task_started 또는 Claude의 사용자 턴 시작을 기준으로 초 단위 갱신한다. 기록을 찾지 못한 경우 Herdr status_ms를 사용한다. 완료 세션에는 타이머를 표시하지 않는다.

목록 메타데이터는 JSONL을 뒤에서 64KiB 블록으로 읽어 구한다. 압축 기록은 순차 처리하며 전체 이벤트를 메모리에 쌓지 않는다. UI 검사 47개, Python 12개, Node 9개 통과. 폰에서 실제 응답 순서·작업 우선 배치·초 단위 타이머·가로 넘침 없음을 확인했다. 전송 상태 검사는 가상 브리지로 수행했으며 실제 에이전트에 시험 메시지를 보내지 않았다. 0.4.0 APK 설치와 브리지 재시작 완료.
